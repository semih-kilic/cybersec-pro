Getting Started

1.1 Creating Your Account

1
Sign up

Visit semihkilic.com/dashboard/login and create your account with email or Google/GitHub SSO.

2
Verify your email

Check your inbox for the verification link. Takes less than 1 minute.

3
Add your first domain

Enter the URL of the website or application you want to scan. We'll verify ownership via DNS TXT record or HTML meta tag.

4
Invite team members

Add colleagues from Settings → Team. Assign roles: Admin, Analyst, or Viewer.

What happens during a scan

Our engine runs automated security checks against your target. All tests are non-invasive — your systems remain fully operational. You can monitor progress in real-time from your dashboard.

How long it takes

Quick Scan: ~30 minutes. Full Scan: ~2 hours. Times vary based on target size and complexity.

1.3 Dashboard Overview

Security score explained

Your security score (0-100) reflects the overall security posture of your assets. It's calculated based on the number and severity of findings. Score above 70 = good, 50-70 = needs attention, below 50 = at risk.

Findings by severity

The dashboard groups all findings by severity level (Critical, High, Medium, Low, Info) so you can prioritize fixes.

Historical trends

Track your security score over time. See how each scan compares to previous results and measure improvement.

Compliance status

Quick view of your GDPR, PCI DSS, and ISO 27001 compliance status with pass/fail indicators for each requirement.

Understanding Reports

3.1 Severity Levels

Critical— Fix immediately (< 24 hours)

Active exploitation possible. Data breach or full system compromise risk.

High— Fix within 1 week

Significant vulnerability that could lead to data exposure or unauthorized access.

Medium— Fix within 1 month

Moderate risk. Usually requires specific conditions to exploit.

Low— Fix when convenient

Minor issue with limited direct impact. Best practice improvement.

Info— Good to know, no immediate action

Informational finding. No direct security risk but worth noting.

3.2 Report Sections

ES
Executive Summary

For non-technical stakeholders. Plain-language overview with risk score and key findings.

VD
Vulnerability Details

What was found, why it matters, and what the business impact would be if exploited.

FR
Fix Recommendations

Step-by-step instructions to resolve each finding. Written for developers and IT teams.

CS
Compliance Status

GDPR, PCI DSS, OWASP, ISO 27001 pass/fail status aligned with regulatory requirements.

HC
Historical Comparison

Compare with previous scans. Track progress over time and see which issues have been resolved.

API Documentation

5.1 Authentication

Getting API keys

Navigate to Settings → API Keys in your dashboard. Generate a new key and store it securely.

# Example: Authenticate with your API key
curl -H "Authorization: Bearer YOUR_API_KEY" \
https://api.semihkilic.com/v1/scans
Rate limits
Starter: 100 req/hr Professional: 1,000 req/hr Enterprise: 10,000 req/hr
Best practices
  • •Never expose API keys in client-side code
  • •Rotate keys every 90 days
  • •Use environment variables for key storage

5.2 Endpoints

POST /v1/scans

Start a new security scan.

// Request body
{
"target": "https://example.com",
"type": "full",
"notify": true
}
GET /v1/scans/{id}

Get scan results by ID. Returns status, findings, and summary.

GET /v1/domains

List all verified domains in your account.

POST /v1/domains

Add a new domain for scanning. Requires DNS or meta tag verification.
